descriptionThe security sub-KG, split on WHERE A VALUE CROSSES A BOUNDARY rather than on attack name. The owner asked for it on 2026-09-25 (paraphrased: a cybersecurity sub-KG in tools, injection first, consolidating the many related skills already scattered across the folio and content layers) and chose scope 2+3: consolidate the scattered pieces AND audit every I/O site. The axis matters: an attack-name split ("XSS", "path traversal", "command injection") files one rule in three places, because the same value crossing the same boundary is all three depending on the sink. A boundary split asks the question a reader actually has at the call site: this value came from outside, what may I do with it? Every entry here existed before the package did and was stranded — `check-workflow-injection.ts` in scripts, `resolveWithin` in one server script, `translation_security.py` in the translation tooling, and the XSS rules in a bean. Beans `6bhf`, `1wef`, `fuzm`, `q2wm`.
