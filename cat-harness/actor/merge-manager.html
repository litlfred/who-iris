titleMerge manager
descriptionThe agent session that holds the merge-steward lane on one or more repositories and runs its watch loop (`merge-manager-watcher`, Process_MergeManagerWatch): it wakes on a timer, on PR events, when a main run finishes, or on a sibling's message; it reads the open PRs, the runner queue, main's verdict and the PR owners live; and it routes each reading to the merge train, a saturation meta-merge, or a stalled-agent takeover. It is the only session that merges or re-pins, in any repository (owner rulings, 2026-11-13); siblings send it the six-line request, or repin+merge: for a PR that is green except for a re-pin. One live session holds the lane per repository, and announces `merge manager: <session id>` to every sibling and the owner when it takes the lane, and to whom when it hands it over. When none is active the siblings elect one (the owner of the P0 PR, else the earliest-created active session), and a lone session is its own merge manager. Siblings send it a six-line merge request (PR and head SHA, session URL, explanation, rendered preview, what to look for, the CI verdict on that head), which it posts in its chat before asking the owner by card. An agent with no chat to it, such as a local agent, signals on its own PR instead: ready for review and the label `ready-to-merge` (green) or `needs-repin` (green except for a re-pin); every sweep reads the PRs carrying either label, and only the merge manager acts on them. It acknowledges each request within about 10 minutes and posts a heartbeat with each sweep (every 10-15 minutes while a P0 is in flight, 30 otherwise); like any agent it may stall, and a sibling whose request goes unacknowledged for about 30 minutes, or whose merge manager's session is inactive, re-elects without it. It merges only on the owner's explicit OK, given in its own session as one card per batch, holds and releases the swarm around every batch landing, and reports what landed and main's verdict.
