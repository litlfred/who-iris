Description

A layer's release addresses: where its identifiers live for the major version it declares.

One form, the major (owner, 2026-10-23, option "B. Major in address")

Every address carries the MAJOR only — <iriBase>v<major>/ — whoever reads it: a namespace, a schema $id, a BPMN xmlns, a JSON-LD @id, and a page a person reads alike.

| audience | form | example (bootstrap 0.1.1) | |---|---|---| | an agent or program — a namespace, a schema $id, a BPMN xmlns | <iriBase>v<major>/ | …/bootstrap/v0/ns/ | | a person — a page to read | <iriBase>v<major>/ | …/bootstrap/v0/ |

The exact release a reader gets is fixed by its PIN (index.lock.json, the needs pins), which already names the commit, not by the address. This is the promise a $schema tag already makes (tagCompatible: any tag of the same major reads): within a major, a minor or patch adds and never breaks, so only a breaking change — a new major — changes an address.

Before this ruling (owner, 2026-09-29) the program-read form carried the full semver, so every patch rewrote about a thousand literal copies across the layers for no reader's benefit. agent and human are both kept so a caller still says which audience it means; they are equal by the ruling.

Derived, never typed

iriBase and version are written once, in the layer's declaration. Everything here is computed from them; a generator or template that needs an address asks releaseIris (or reads the release variable it is handed) instead of spelling one out. The copies that cannot be computed at read time — an xmlns attribute in 70 BPMN files, a value in a code list — are kept at the declared major by scripts/iri-sync.ts, whose --check is a gate.
